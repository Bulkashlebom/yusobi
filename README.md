# Ysobi Shop

Telegram-магазин на Telegraf и SQLite. Поддерживает локальный запуск на Windows, панель запуска на этом ПК, подключение владельца одноразовой командой, собственные товары и чтение каталога Aviedo.

Автоматическая оплата и закупки через Aviedo ещё не включены: клиент поставщика в этой версии предоставляет только GET-запросы. Полный цикл оплаты, закупки, восстановления заказа и возврата должен быть завершён до включения автоматических продаж.

## Запуск на Windows

Нужен Node.js 22.12 или новее. Откройте `Запустить Ysobi Shop.cmd`. При первом запуске устанавливаются зависимости, затем открывается локальная панель. Введите в ней токен существующего @YsobiShop_bot из BotFather. Токен проверяется через Telegram и сохраняется в `.env` рядом с программой.

Панель покажет одноразовую команду `/connect …`: отправьте её своему боту в личном чате, чтобы назначить себя владельцем. Команда действует 15 минут и перестаёт работать после первого успешного подключения. ID администратора сохраняется локально. Другой пользователь не может получить управление по одному лишь первому обращению к боту.

Панель слушает только `127.0.0.1`, проверяет Host, Origin и случайный ключ запросов. Секреты не возвращаются через API состояния. При наличии старого локального проекта Aviedo → FunPay можно перенести только ключи Aviedo:

```powershell
node local-control.js --open --supplier-env "C:/path/to/aviedo-funpay/.env"
```

Другие ключи из этого файла не копируются. Настройка сохраняет отдельную локальную SQLite-базу. Старые заказы автоматически не импортируются.

Программа перезапускает бота после временного сбоя и не даёт Windows автоматически уснуть, пока бот запущен. Ручной сон, отключение питания и отсутствие интернета прерывают работу. Кнопка остановки завершает дочерний процесс через IPC; закрытие родительского процесса также останавливает бота. Конфликт с другим экземпляром и недействительный токен требуют исправления вместо бесконечных перезапусков.

## Отдельный процесс и сервер

Заполните `.env` по `.env.example` либо переменные размещения. Запускайте `npm start` или `node bot.js`. Второй способ сохранён для существующих настроек Railway. Для SQLite нужен постоянный `DATA_DIR`; на Railway его обычно монтируют в `/app/data`.

`/health` показывает, что процесс доступен. `/ready` возвращает 200, когда опрос Telegram действительно получает ответы, и 503 при отсутствии готовности. Прогресс проверяется по `getUpdates`; проверка `getMe` не заменяет проверку опроса. При переподключении очередь обновлений сохраняется. В одном процессе работает один цикл запуска.

При фатальной ошибке процесс завершается для внешнего перезапуска. Код 73 означает конфликт другого экземпляра, 78 — отклонённый токен. Некорректное состояние SQLite с WAL без основной базы останавливает запуск вместо создания пустого магазина. SQLite-файлы и `.env` не должны попадать в Git, Docker-контекст и архив исходников.

## Aviedo

`AVIEDO_TOKEN` и `AVIEDO_SECRET` задаются локально или в переменных сервера. В личном чате администратора доступны `/supplier` и `/supplier_product ID`. Команда `npm run supplier:check` читает баланс и количество товаров. Клиент подписывает точный путь с query по HMAC-SHA256, не следует редиректам и учитывает ограничение частоты запросов.

`catalog.js` формирует черновики карточек из данных Aviedo, сохраняет регион, номинал и способ исполнения. Розничные цены автоматически не назначаются. Ручные услуги, товары с перепиской и дополнительными действиями покупателя требуют соответствующих сценариев обработки.

Для цифровых товаров внутри Telegram требуется [Telegram Stars](https://core.telegram.org/bots/payments-stars). Перед продажами нужно завершить проверку оплаты, цены, очередь закупки с защитой от дублей, выдачу и возвраты.

## Проверка

```powershell
npm ci --ignore-scripts
npm run check
npm test
```

Тесты проверяют реальный импорт Telegraf и SQLite на временных данных, меню, подключение владельца, защиту локального API, оба способа запуска, переподключение и остановку, готовность, подпись Aviedo и обработку ошибок. Сетевые вызовы Telegram в автоматических тестах заменены. Приложение проверялось на Windows с Node.js 24; контейнер Linux требует отдельной проверки.
